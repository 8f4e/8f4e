# Editor WebMCP Bridge

- This is a page-owned adapter, not an editor plugin. Accept exactly one editor with a public editing handle at construction.
- Keep WebMCP API detection, schemas, tool registration, and AbortSignal cleanup here. Do not add browser agent concepts to editor-core or editor-state.
- Allow one active bridge per document. Keep tools bound to their original editor; use disposal and reconstruction when the host replaces an editor.
- Delegate edits and history to `editor.editing`, and shared view navigation to `editor.navigation`. Never mutate editor state or implement compilation inside tool callbacks.
- Keep the editor API's complete structured snapshot intact. `get_project` exposes only the currently expanded group or root as one 8f4e source string, with deeper groups left as shells. It accepts no group selector. Navigation tools change the editor's visible group and return location only. Block reads and updates resolve type and name only within that same scope; metadata and batch edits must also stay in the current scope. Return plain source strings from get_project and get_block. Keep revision tracking inside this bridge, outside tool inputs. Expose no block identifiers or line-range index. Keep optional location/history information in get_project_metadata. All block selectors, including metadata lookups and batch edits, use source type and name. Resolve them to editor handles internally and strip editor identifiers from write results. Filter duplicate data and convert string/line-array formats only in this adapter. Fetch additional block metadata through its dedicated read tool.
- Cache the exact revision only after successful source reads and writes, including undo/redo. Reject writes before the first source read or after external source changes, requiring a source re-fetch. Metadata, diagnostics, navigation, failed reads, and failed writes never acknowledge changes. Reset this cache with the bridge lifetime. Pass the cached matching revision to the existing editor API, and return simple write confirmation strings.
- Position writes belong in source `@pos` directives. Expose insert, update, and delete operations without separate coordinate fields or a move operation.
- `patch_block` uses the same current-scope type/name selector and revision checks as updates. Replace one exact nonempty source span with literal text, reject missing or ambiguous matches, and delegate the resulting source to the public editing handle as one undo step.
- Compiler diagnostics arrive through an optional injected read handle. Preserve its revision and readiness information.
- Unsupported browsers retain ordinary editing. Failed or cancelled registration must remove partial tools and release the document for a replacement bridge.
- Verify `build`, `test`, and `typecheck` through `npx nx run @8f4e/editor-webmcp:<target>`. Gallery lifecycle checks live in `@8f4e/8f4e-website:test:browser`.
