# Editor WebMCP Bridge

- This is a page-owned adapter, not an editor plugin. Accept exactly one editor with a public editing handle at construction.
- Keep WebMCP API detection, schemas, tool registration, and AbortSignal cleanup here. Do not add browser agent concepts to editor-core or editor-state.
- Keep host detection and lifecycle in `src/index.ts`, execution/error handling in `src/tool.ts`, and named tool definitions with their schemas and handlers in `src/editor-tools.ts` and `src/reference-tools.ts`. Derive accepted argument keys from schema properties. Editor tools own the current-scope lookup and revision baseline; reference tools have no editor binding. Keep help guidance explicit in tool descriptions, independent of read-only annotations.
- Bundle `get_help`, `search_docs`, `get_docs`, `search_examples`, and `get_example` with this package, without host-provided content. Use `@8f4e/vite-plugin-sources` collections in the content-generation build for compiler/editor Markdown and example block/project source. Reuse the example-modules package's catalog and public-block helpers through its public subpath exports. Keep the search index eager and full source in lazy package modules. Reference tools never acknowledge live source revisions or change state/navigation.
- Catalog generation and builds use `production` / `^production` inputs. Keep compiler/editor docs and example source inputs explicit; browser/unit fixtures must not invalidate the catalog. Production generator imports are real build dependencies even when listed in `devDependencies`.
- `generate-content` generates ignored `src/generated/` files through a temporary Vite SSR build under `.content-generator/`. Build/test/typecheck depend on it. Keep docs and example sources in Nx inputs and dependencies so cached builds include matching content. Typecheck both browser code and the generator/configuration. Browser tests consume the built bridge package.
- Keep document/example analysis pure in `scripts/catalog.ts` and share fence/heading detection through `scripts/markdown.ts`. `scripts/generate-content.ts` owns source discovery and file output. Cover analysis edge cases with fixtures in `scripts/catalog.test.ts`; retain the bundled-content and public-tool regression tests.
- Preserve 8f4e sigils and identifier spelling when converting Markdown to display text or normalizing search terms. Summarize/index a documentation section's own content; include enclosing rules only in full reads. Derive example summaries from prose comments or compiler-parsed project notes, and index the full descriptive prose without exposing internal search terms in results. Keep purpose words in example source descriptions rather than a bridge-specific synonym map.
- Allow one active bridge per document. Keep tools bound to their original editor; use disposal and reconstruction when the host replaces an editor.
- Delegate edits and history to `editor.editing`, and shared view navigation to `editor.navigation`. Never mutate editor state or implement compilation inside tool callbacks.
- Read existing live data through `editor.state` and revisions through `editor.editing.getRevision()`. Collect and format results synchronously, before yielding; do not clone the entire editor graph or introduce a parallel snapshot model. `get_project` exposes only the currently expanded group or root as one 8f4e source string, with deeper groups left as shells. It accepts no group selector. Navigation tools change the editor's visible group and return location only. Block reads and updates resolve type and name only within that same scope; metadata and batch edits must also stay in the current scope. Return plain source strings from get_project and get_block. Keep revision tracking inside this bridge, outside tool inputs. Expose no block identifiers or line-range index. Keep optional location/history information in get_project_metadata. All block selectors, including metadata lookups and batch edits, use source type and name. Resolve them to editor handles internally and strip editor identifiers from write results. Filter duplicate data and convert string/line-array formats only in this adapter. Fetch additional block metadata through its dedicated read tool.
- Cache the exact revision only after successful source reads and writes, including undo/redo. Reject writes before the first source read or after external source changes, requiring a source re-fetch. Metadata, diagnostics, navigation, failed reads, and failed writes never acknowledge changes. Reset this cache with the bridge lifetime. Pass the cached matching revision to the existing editor API, and return simple write confirmation strings.
- Position writes belong in source `@pos` directives. Expose insert, update, and delete operations without separate coordinate fields or a move operation.
- `patch_block` uses the same current-scope type/name selector and revision checks as updates. Replace one exact nonempty source span with literal text, reject missing or ambiguous matches, and delegate the resulting source to the public editing handle as one undo step.
- Compiler diagnostics arrive through the optional injected `getCompilerDiagnostics` read handle and are exposed as `get_compiler_diagnostics`. Preserve its revision and readiness information.
- Unsupported browsers retain ordinary editing. Failed or cancelled registration must remove partial tools and release the document for a replacement bridge.
- Verify `build`, `test`, and `typecheck` through `npx nx run @8f4e/editor-webmcp:<target>`. Real-editor command tests live in `browser-tests/` and run through `npx nx run @8f4e/editor-webmcp:test:browser`. Keep only gallery loading/bridge replacement checks in `@8f4e/8f4e-website:test:browser`.
